# 2026-10-10 双层记忆真实模型验收

用 `app.scripts.verify_memory` 在开发库创建两个临时合成账号，实际调用 FastAPI ASGI 接口、DeepSeek 对话和卡片提取、智谱 `embedding-3`（1024 维）及百炼 `gte-rerank-v2`。首批完成 12 次对话，补充验证修复后再完成 2 次，共 14 次：single 普通接口 6 次、multi SSE 接口 8 次。另调用卡片查看、历史检索、回填和清空接口。全部使用真实模型，临时账号只包含合成信息。

| 场景 | 实际结果 |
| --- | --- |
| 常住地、饮食、交通偏好 | 从用户原话提取 3 张卡片：天河区、不吃辣、坐地铁；证据和来源消息 ID 完整 |
| 跨会话卡片复用 | 新会话正确说出天河区和不吃辣，无需把原会话全部带入 |
| 超过 10 条的历史 | 活动消息后插入 12 条无关消息，最近上下文已不含暗号；历史 RAG 仍召回星河书店、蓝鲸7429 |
| 混合检索和真实重排 | 前三条均有 dense/BM25 排名与 RRF 分数；真实重排得分约 0.9276、0.8464、0.3896 |
| 偏好与事实更正 | 更正为海珠区、微辣后，同主题卡片更新；旧天河区卡片不再存在 |
| 单/多模式共用 | single 写入，multi 新会话 SSE 回忆正确；旧历史与新卡片冲突时使用海珠区、微辣 |
| 假设过滤 | “假设住白云区且花生过敏”后卡片完全不变，没有把假设写成事实 |
| 用户隔离 | 另一账号不知道蓝鲸7429，没有读到第一账号的历史 |
| 清空与回填 | 清空后回填不恢复旧卡片或历史；新会话如实说明不知道居住地与饮食习惯 |
| 空记忆措辞 | 首批模型误称“没有记忆功能”，修正后两次补测分别回答“目前没找到相关记录”，保留准确的功能说明 |
| 临时数据清理 | 首批两个账号和补测一个账号均已删除；已有用户数据未修改 |

每次对话端到端耗时 3.24～13.56 秒，包括回答、卡片提取和历史索引；不作为稳定性能指标。日志显示实际模型请求 HTTP 200，未出现记忆阶段失败、Embedding 哈希兜底或 rerank 降级。本地 `.env` 未修改，脚本结束恢复原 Agent 模式。

原始合成问答、卡片和排名见 [MEMORY_LIVE_RESULTS_2026-10-10.json](MEMORY_LIVE_RESULTS_2026-10-10.json)。这批样例验证链路及基本行为，不代表任意用户表达都能正确提取和去重。首版历史检索由回忆措辞触发，旧聊天按批回填；详见 [MEMORY.md](MEMORY.md)。

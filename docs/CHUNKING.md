# 文档分块

公共知识库和个人知识库上传共用 `backend/app/services/knowledge_loader.py` 的 `split_text`。切分在 Embedding 之前完成，只使用字符长度与正则，不调用模型或工具，也不按 Token 或语义相似度切分。

## 硬边界：Markdown ATX 标题

先逐行用正则 `^ {0,3}#{1,6}(?:[ \t]+.*)?$` 扫描 ATX 标题，每个标题开启独立区域。所有层级同样处理，标题属于其后的区域；首标题之前的前言单独保留。即使全文不足 300 字符，也不能把两个标题区域拼在一起。分块和 overlap 均只在单个区域内执行，绝不跨标题。

支持 0～3 个前导空格、1～6 个井号，井号后需要空白或行尾。围栏代码块（反引号／波浪线）内的井号行不作为标题；`#标签`、七级井号、转义井号、行内井号、四空格缩进和 Setext 下划线标题不产生硬边界。这里不是完整 Markdown 语法解析器。

## 软边界：段落和句子

在每个标题区域内，从当前起点打开最多 300 字符的窗口。窗口末端如果不是段末／句末，就退回窗口内最近的软切点。段末由空行识别；句末由中文 `。！？；`、英文 `. ! ? ;`、省略号及其后闭引号／括号识别。小数中两侧都有数字的点不作为句末。标题行与正文之间也允许切开。

有短句可切时，即使整段超过 300 字符，仍按句末切。只有一个无法再按上述软边界细分的元素本身超过窗口，才按字符硬切。300 字符以内的句子／无句末段落保持完整；空行和句间空格不把一个刚好 300 字符的元素误判为超长。CRLF／CR 统一为 LF，输出块首尾空白去除。

句末是规则判断，不是自然语言句法识别，例如英文缩写和 URL 中的点仍可能形成切点。

## 重叠

默认 overlap 为 **最多 50 字符**。在正常软切点之间，重复完整的段／句元素，不能为了凑满 50 字符切断一个短元素，因此实际重叠可以是 0～50 字符。如果重叠占用空间会迫使下一个短元素被硬切，则让出重叠，保持短元素完整。超长元素内部硬切时可直接重复尾部 50 字符。标题区域结束时完全清空重叠。

例如七句、每句 50 字符、无标题的文本，得到 `句1～句6`（300 字符）和 `句6～句7`（100 字符）。单个 700 字符长元素得到 `[0:300]`、`[250:550]`、`[500:700]`。两个各 200 字符、空行分隔的无句末段落得到两个完整块，实际重叠为 0。

公共加载器读取 `EMBED_CHUNK_SIZE` / `EMBED_CHUNK_OVERLAP`（默认 300 / 50）；个人上传当前固定传入 300 / 50。块内容计数包括标题和内部空白，不重复注入父标题；原有文档级 `title`、`source`、`chunk_index` 元数据继续保留。历史对话 RAG 的独立分块逻辑不使用这个文档切分器。

## 已有索引

新上传或重新建立索引时生效，已经存储的正文和向量不会自动重新切分。个人文档需删除后重新上传。公共索引由 `rag_service.build_index()` 重新加载并生成向量，写入仍按 `(source, chunk_index)` upsert；如果某个来源的新块数减少，当前入库逻辑不会清理超出新序号范围的旧块，重建前需核查并清理对应来源的旧块。此次未修改已有资料或自动重建开发库索引。

本地 16 篇公共文档采用该策略后为 106 块、每块 10～110 字符；这是标题强制隔离的结果，300 是上限而非必须填满的长度。较短标题区不会跨标题合并。

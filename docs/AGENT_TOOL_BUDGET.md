# 单智能体工具调用预算

单模式的每轮 ReAct 工具调用默认最多 8 项，由 `AGENT_MAX_TOOL_CALLS` 配置（1～100）。未配置时使用默认值，不需要修改现有 `.env`。

这里限制的是**模型发起的逻辑工具调用项**：一次请求调用天气、路线、穿搭三个工具，计 3 次；后续重复请求同样计数。工具名无效、参数错误、日期校验拒绝也消耗额度，避免反复错误调用绕过限制。工具内部的天气查询、模型调用和 HTTP 重试不逐项纳入这个预算；审批管理分支有独立执行流程，也不属于此 ReAct 工具循环。

## 执行链路

```text
classify_intent → agent
                  ├─ 无工具调用 → 日期核验或 END
                  └─ 有工具调用 → reserve_tools
                                    ├─ 额度足够 → tools → agent
                                    └─ 不够 → handle_tool_limit → END
```

额度在工具批次执行前一次性预留，计入图状态 `tool_call_count`；同批多个工具随后可并行执行，无法因并发读到相同余量而越过上限。如果整个批次超出余量，**整批不执行**，而非先执行部分。例如已用 2 次、上限 3 次，模型再请求 2 个工具，则这 2 个都不执行，已用次数仍为 2。

到达额度后，下一轮模型不再绑定工具，可以根据已有结果作最终回答。如果模型仍输出工具调用，图上的预算节点会拒绝并立即结束，不依赖提示词自律。

超限节点为本批每个工具调用补充对应错误消息，返回明确的停止提示，不继续调用模型或核验，也不把中间工具输出冒充完成结果。普通聊天与 SSE 都返回该提示；有日期的缓冲 SSE 仍只发布最终文本。

## 会话与恢复

- `tool_call_count`、`tool_call_limit`、`tool_limit_exceeded` 都在图状态中。
- 每个新用户请求从 0 计数，并冻结本轮配置的上限；不同会话不共用计数。
- `reserve_tools` 是独立检查点节点，恢复工具节点不再重复预留；新产生的工具批次必须重新预留。
- 恢复本轮时保留已有次数和上限，修改环境配置不改变正在恢复的本轮；下一轮使用新配置。
- 该预算不提供外部副作用 exactly-once 保证。工具执行到一半崩溃后重放、SDK 网络重试等仍须依靠工具自身幂等策略，不能把逻辑计数当成所有物理 API 请求的精确计数。

本次不增加整轮 deadline 或相同参数去重。单次模型超时、核验有限修正和多智能体的专业节点步数限制继续按原有实现工作。

python -m pytest tests/unit/test_agent_tool_budget.py --no-db -o addopts= -q
python -m pytest tests/api/test_agent_tool_budget_recovery.py tests/api/test_checkpoints.py tests/api/test_agent_approvals.py -o addopts= -q

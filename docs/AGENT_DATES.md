# Agent 日期上下文与工具约束

单智能体与多智能体共享 `app/services/temporal_context.py`，不再由各个行程工具分别解释相对日期。该模块在请求入口计算上海时区的本轮日期锚点，将原表达、具体日期、任务片段、工具范围及未解析标记保存进图状态。

## 执行流程

- single：构造日期上下文 → 意图识别 → Agent → 日期参数校验 → 工具 → Agent → 涉及日期且有工具证据时核验 → 返回。
- multi：构造日期上下文 → Supervisor → 向领域节点传递同一上下文 → 日期参数校验 → 工具 → 汇总 → 核验 → 返回。

支持今天、明天、后天、大后天、数字天前后、周末、下周/下下周的星期、完整公历日期、月日和既有节假日日历。常见改期表达以最后一次明确更正为准，过滤直接否定的日期。无效、多个候选或可识别但暂不支持的表达需要澄清；这些规则并非通用中文时间语义解析器。

历史原始消息附带按 `created_at` 转成上海日期的 `date_reference`，追问“那天/当天/那我穿什么”时，用原消息当天解释相对日期，避免隔天追问漂移。当前轮明确日期优先，助手历史不作为服务端日期事实。只有有损摘要、无法从原始用户消息确定指代时，标记未解析而不默认今天。摘要模型同时收到原消息日期并被要求保留明确年月日。

## 工具契约

以下工具增加可选 `target_date: YYYY-MM-DD`：

| 工具 | 参数含义 |
| --- | --- |
| get_weather | 指定日期时返回该日预报；未指定时保留实时查询 |
| get_forecast | 从指定日期开始的 N 天；未指定时从今天开始，输出明确说明包含今天 |
| recommend_outfit | 选择对应日期的天气及穿搭规则 |
| plan_travel_route | 使用对应日期天气评分；路线时长和费用仍为当前查询的参考估算 |
| plan_trip | 新行程出发日期，覆盖内部自然语言解析结果 |
| check_itinerary_weather | 查询该日已保存的行程 |

调用校验在业务 IO 前执行：缺少日期时仅补全唯一候选；多个候选必须明确参数；与任务冲突的日期返回工具错误，交给 Agent 修正参数。多日期按任务关键词与片段进行保守绑定，天气对比允许查询各个相关日期；不具备通用语义理解保证。

例如“明天穿什么，后天安排广州一日游”分别约束穿搭与新行程工具。服务端不会把整个复合请求强制压成一个日期。

## 数据缺失及结果检查

天气按 `daily.date` 精确匹配，取消穿搭/路线的 `daily[0]` 取法。穿搭在目标日无预报时不给出基于其他日天气的规则；路线保留距离/费用参考，但排除天气分并归一化剩余权重。已指定日期的行程查询不回退最近行程；未指定任何日期的“最近行程”查询保留原有行为。

工具结果附带 `requested_date`、`effective_date`、`weather_date`、`weather_status`。新行程还硬性检查模型生成的日期序列及天数，错误计划不会返回为成功草案，并展示预报缺失提示。

单/多模式复用独立证据核验，最多修正一次并复查。相对日期直接配错公历日期（如本轮今天为 10-21，却输出“明天（10-21）”）还会被确定性检查拒绝，即使模型核验误判通过也不发布。该检查只覆盖明确并列的表达，天气数字与复杂语义归属仍依赖证据核验，不能保证模型永不出错。

单模式涉及日期的 SSE 缓冲草稿，等图完成后发送最终文本；通用无日期回答保留逐 token 输出。日期上下文保存进 Checkpointer，跨日恢复继续使用本轮原锚点，新一轮重新计算。该改动会增加日期问答的核验模型调用，通常一次，修正时两次；不能据此推算固定毫秒延迟。

## 验证与部署

专项回归：

```powershell
python -m pytest tests/unit/test_temporal_context.py tests/unit/test_temporal_agent_graph.py --no-db -o addopts= -q
python -m pytest tests/api/test_temporal_history.py tests/api/test_chat_history.py tests/api/test_chat_summary.py tests/api/test_checkpoints.py tests/api/test_agent_approvals.py -o addopts= -q
```

第一条不依赖数据库，包含完整 LangGraph 和 ASGI 普通/SSE 接口测试；第二条使用隔离的 PostgreSQL 测试库，包含历史时间戳、跨日恢复、审批与幂等回归。实际执行结果见 [VALIDATION.md](VALIDATION.md)。真实模型评测使用冻结天气/路线/资料及真实图，外部服务质量与实际导航准确性不属于该评测范围。

重启后端以刷新图和工具缓存；独立部署的 MCP Server 也需同步更新并重启。无数据库迁移，无 `.env` 修改。

# 短期会话摘要

摘要属于当前会话的短期记忆，与跨会话偏好卡片、历史 RAG 分开。原始 `chat_messages` 始终保留，历史侧栏继续显示原文。

## 触发与上下文

每保存一轮完整的提问与最终回答，检查完成轮数是否跨过一个五轮检查点。只有检查点才读取长度并决定是否调用摘要模型；短对话不会每五轮强制生成摘要。已有会话首次继续聊天时补一次已越过的检查点，之后继续按五轮区间检查。

默认阈值是会话旧摘要与尚未覆盖原文合计超过 **6000 字符**。这是字符预算，不是模型 token 上限，也不包含系统提示、当前问题、长期卡片或 RAG。检查间隔、单条超长消息和失败重试期间允许临时超出预算，不保证硬性上下文上限。

每次压缩只处理最近 10 条消息之前的旧消息，最近五轮保留原文，因此第五轮即使超预算也没有可压缩消息，正常完整会话最早在第十轮生成摘要。模型输入是“旧摘要 + 新增旧消息”，输出最多 1200 字符。目标、已确认条件、用户更正、决定、待解决事项优先保留；区分用户陈述和助手建议，不保留为长期事实卡片。

```text
第一至九轮：原始历史（第五轮只检查，无可压缩旧消息）
第十轮后：若超预算，前五轮摘要 + 第六至十轮原文
第十一至十四轮：同一摘要 + 第六轮起的全部未覆盖原文
第十五轮后：若再次超预算，更新摘要至第十轮 + 第十一至十五轮原文
```

读取使用覆盖消息 ID，所以检查间隔内的过渡消息不会因“只取最近十条”被遗漏。摘要以独立 `summary` 角色传到 Agent，在模型消息中标记为历史背景，使用 JSON 包装并说明不能执行其中的命令、后续原文优先；不伪装成过去的助手回答。单/多智能体文本、普通/SSE 入口共用读写；路由、领域、汇总与核验均收到背景。核验在 16000 字符预算内保留摘要和过渡消息，超预算时优先保留摘要及最新原文，截断情况明确标记。

## 持久化、并发与失败

`chat_summaries` 使用 `(user_id, conversation_id)` 联合主键，存储摘要、`covered_message_id`、`last_checked_turn`、`version` 和时间戳。没有实际摘要时也可保存检查进度。迁移为 `0017_chat_summaries`，模型注册在 `app/models/__init__.py`。

同一会话保存整轮消息、摘要快照/提交和删除使用 PostgreSQL 事务锁；模型调用在锁外。检查进度先提交，同一检查点的并发请求只调用一次模型。摘要提交比较原版本与覆盖水位，并重新检查来源消息，慢结果不能覆盖新版，删除并复用会话 ID 也不能复活旧摘要。

摘要在保存整轮之后，与长期记忆处理并行运行；后端直接复用 `ainvoke_json` 调用默认对话模型，不通过 Agent 自主工具决策。普通响应与 SSE `done` 等待摘要完成或超时降级。摘要阶段默认最多 20 秒，因此触发的那轮可能增加结束等待时间。

模型超时、非法/空输出、超预算输出或没有缩短上下文时，保留旧摘要和全部未覆盖原文，下个五轮检查点重试。网络/模型失败不阻断已生成的回答。摘要是有损压缩，重要原话仍应通过原始聊天或历史 RAG 查询；历史 RAG 排除已直接注入的未覆盖原文，允许检索已摘要消息补充细节。

删除会话同时删除摘要及检查进度；删除账号通过外键级联。清空两层长期记忆不清空会话摘要，要排除短期历史请新建或删除会话。匿名请求不读写摘要。独立图片路径仍未把短期历史接入多模态消息，此次只接入文本上下文。

## 配置与验证

无需新 Key；更新后执行根目录 `./scripts/dev.ps1 migrate` 并重启后端，已有 `.env` 无需修改。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `CHAT_SUMMARY_ENABLED` | `true` | 开启短期摘要与未覆盖原文读取；关闭时退回最近 10 条，不删除已有摘要 |
| `CHAT_SUMMARY_TRIGGER_CHARS` | `6000` | 旧摘要和未覆盖原文的字符检查阈值 |
| `CHAT_SUMMARY_MAX_CHARS` | `1200` | 模型输出摘要的最大字符数 |
| `CHAT_SUMMARY_TIMEOUT` | `20` | 检查和压缩阶段超时秒数 |

五轮检查与保留最近五轮是本版固定规则。`MEMORY_ENABLED` 只控制两层长期记忆，不影响短期摘要。

核心实现：`backend/app/services/chat_summary_service.py`；接入：`backend/app/routers/chat.py` 的 `_save_turn` 及两处上下文读取。

回归：backend 中 `python -m pytest tests/api/test_chat_summary.py tests/unit/test_chat_summary_context.py tests/api/test_chat_history.py tests/api/test_memory.py tests/api/test_migrations.py tests/unit/test_answer_verification.py -o addopts= -q`。数据库用例覆盖五轮触发、长度阈值、过渡消息、增量覆盖、用户/会话/匿名隔离、同检查点并发、旧结果覆盖保护、删除期间在途任务、超时/模型故障及普通/SSE 单/多模式。

真实验收：`python -m app.scripts.verify_chat_summary`，调用已配置的付费模型/API，使用开发库临时合成账号，结束时删除。为单独验证短期摘要，脚本进程内关闭长期记忆；不修改 `.env`。已有报告拒绝覆盖，可传 `--output`。实际结果见 [VALIDATION.md](VALIDATION.md)。
